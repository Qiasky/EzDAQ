# XPort 韩感温湿度传感器驱动详细使用说明

更新日期：2026-10-05。适用设备：本次实测的韩感 LH8950 / LHG8950 温湿度传感器，内置经典 Lantronix XPort 网络模块。

本说明对应 EzDAQ 仓库中的桌面工具、Python TCP 采集驱动和微信云开发接入。参数依据用户提供的 LabVIEW 程序及实际报文确定；其他型号、其他固件或不同采样格式须重新核对。

## 1. 先选使用方式

| 需求 | 使用入口 | 是否向微信云端上报 |
| --- | --- | --- |
| 查 IP、核对 MAC / 端口、修改 IP | `apps/xport-tool/bin/XPort温湿度工具.exe` → 查找 / 改 IP | 否 |

一次只让一个采集程序读取同一台模块，避免桌面工具、LabVIEW 与上云进程竞争 TCP 连接。两台不同 IP 的模块可以分别读取。

## 4. 接线与电脑网络

### 4.1 通过家中路由器读取

1. 传感器供电，将 XPort 网线插入路由器 LAN 口，确认网口灯亮 / 闪。
2. 电脑通过有线或 Wi-Fi 接入同一局域网。
3. 在工具上方选择对应电脑网卡，例如 `WLAN · 192.168.31.122/24`。电脑地址会随实际网络变化，不要照抄旧地址。
4. 填设备 IP，例如设备 A 的 `.178` 或设备 B 的 `.201`，端口 `10050`。

典型网络：模块 `192.168.31.201/24`、电脑 `192.168.31.122/24`、路由器 `192.168.31.1`。电脑与模块不能使用相同 IP。

### 4.2 模块直接连接电脑

本次设备 B 的测试配置为：模块 `192.168.31.201`，电脑有线网卡 `192.168.31.200`，两者掩码均为 `255.255.255.0`。工具应选 **以太网**，而不是 Wi-Fi 或 VMware 虚拟网卡。

若电脑有线地址不在相同网段，先查看 `ipconfig`，确认网卡名称。在 **管理员 PowerShell** 中设置临时地址：

```powershell
netsh interface ipv4 set address name="以太网" source=static address=192.168.31.200 mask=255.255.255.0 gateway=none
```

旧设备仍是 `111.111.111.201` 时，本次查配置曾临时使用 `111.111.111.200/24`；设备现在已改为 `.31.201`，无需再设置旧网段。工具读取配置时会要求所选电脑网卡与设备处于同一网段，避免请求走互联网默认路由。

修改前记下电脑网卡的原设置。原来使用 DHCP 的网卡，直连测试结束后可恢复：

```powershell
netsh interface ipv4 set address name="以太网" source=dhcp
```

原来是固定 IP 的网卡应恢复原固定参数。工具中的 **网段帮助** 可以复制临时设置命令，但不会自行修改电脑网卡。

## 5. 用图形界面查找和修改 IP

### 5.1 查找设备

1. 双击 EXE，选择正确电脑网卡。
2. 打开 **查找 / 改 IP**，点 **查找 XPort**。
3. 在列表核对设备标签上的完整 MAC，不只看厂商前缀。
4. 双击设备，或选中后点 **读取选中设备**。成功后显示实际 IP、TCP 端口、掩码与网关。

查找会发送 XPort UDP 广播。电脑已安装 Wireshark / Npcap 时，还会同时监听所选有线网卡的 ARP，辅助寻找本次 `00:20:4A` 模块的未知静态地址。ARP 监听持续约 6 秒，不会自动安装抓包驱动。

找不到时，在查找期间给模块重新上电，促使它发送 ARP。若只发现跨网段地址，先按 **网段帮助** 配好电脑有线网卡，再读取配置。没有广播回复并不必然表示数据端口无法连接。

已知 IP 和 MAC 时，可直接填 **当前 IP / 模块 MAC**，点 **读取选中设备**，不必重复广播查找。

### 5.2 修改 IP，保持端口

以设备 B 为例，目标参数：

| 参数 | 值 |
| --- | --- |
| 模块 MAC | `00:20:4A:B9:93:F7` |
| 新 IP | `192.168.31.201` |
| 子网掩码 | `255.255.255.0` |
| 网关 | `192.168.31.1` |
| TCP 端口 | 保留设备当前值，本次为 `10050` |

操作顺序：读取当前配置 → 填新网络参数 → 点 **保存新 IP** → 核对确认框 → 等待模块保存并重启。

工具会在写入前再次核对 MAC、读取当前完整配置并生成备份。只改 IP、掩码与网关，保留 TCP 端口、串口及其他配置；界面没有修改端口的输入框。

如果新旧地址跨网段，模块重启后旧连接会失效。将模块接回目标路由器，或将电脑有线网卡改到新网段，再 **查找 / 读取选中设备**。收到写入确认只代表模块已接受配置，最终以新地址的 MAC、配置读回与真实采集为准。

显示 **未收到确认** 时，先查找新旧地址并核对设备，不要立刻重复写入。配置口禁用、只读或固件格式不同会显示失败 / 不支持。

### 5.3 原理与备份

网络配置使用 Lantronix CoBos UDP 配置记录。关键参数按 [Lantronix 官方手册附录 B](https://www.lantronix.com/wp-content/uploads/pdf/XPress-DR_User_Guide.pdf)实现，并已在本次 XPort 上验证。

| 项目 | 实现 |
| --- | --- |
| UDP 配置端口 | `30718`，十六进制 `0x77FE` |
| 固件 / 身份查询 | `F6` 请求、`F7` 响应；本工具要求包含完整 MAC 的 30 字节响应 |
| 读取配置 | `F8` 请求、`F9` 响应，4 字节头加 120 字节记录 |
| 写入网络配置 | `FD` 请求，`FB` 确认；模块随后重启 |
| IP 字段 | 记录偏移 `0～3` |
| 掩码字段 | 偏移 `6`，保存主机位数；`/24` 为 `8` |
| 网关字段 | 偏移 `12～15` |
| TCP 本地端口 | 偏移 `20～21`，低字节在前 |

UDP 配置是管理通道，TCP `10050` 是温湿度数据通道。Telnet `9999` 如要求密码，应使用已知管理密码；本工具不会猜密码、恢复出厂设置或改变串口参数。

## 6. 用图形界面实时读取

1. 选择对应电脑网卡。在 **实时采集** 填设备 IP 与 TCP 端口。
2. 默认 **采集周期 10 秒**、**发送后等待 10 秒**、**接收超时 10 秒**。等待值来自原 LabVIEW 使用参数。
3. 点 **开始采集**。首次读数通常需等待约 10 秒；若发生连接 / 收取超时，会更久。
4. 观察温度、湿度、通讯状态、更新时刻和收发 HEX。点 **停止** 结束。

采集周期按一轮开始时间计算；若一轮等待与接收超过周期，完成后开始下一轮。正常界面保留最近收到的 HEX，等待下一轮时仍可查看；状态中的 **上次通讯正常** 指最近一次已完成采样。

| 显示 | 含义 |
| --- | --- |
| 正在连接 / 已连接，等待读取 | 正在执行本轮 TCP 读取 |
| 通讯正常 | 完整帧通过校验，已解析温湿度 |
| 通讯正常 · 湿度原始值 FFFF | TCP 通讯与温度有效，湿度通道无效 |
| 超时 / 连接关闭 / LRC 校验失败 | 本轮失败，数值清空；收到的部分 HEX 保留 |
| 已停止 · 显示最后一次读取结果 | 当前不再采集，界面数值是最后一次结果 |

最近通讯记录保留在界面中，最多 200 行。桌面程序保存连接参数，但不会保存采样历史、自动向云上报或配置开机自启。

## 8. 温湿度原始协议和 HEX 解读

### 8.1 发送帧

驱动将下列 **17 个真实字节** 写入 TCP 套接字：

```text
3A 30 30 30 34 35 30 30 30 30 30 30 38 41 34 0D 0A
```

ASCII 表示：

```text
:000450000008A4\r\n
```

代码中 `\r\n` 表示回车换行两个字节 `0D 0A`。配置 `requestHex` 中空格只便于阅读，不会发给设备。不要把 HEX 文本本身当成另一个 ASCII 字符串发送，也不要追加 Modbus TCP 的 MBAP 头。

帧的冒号、ASCII 十六进制、CRLF 和 LRC 外形遵循 [Modbus ASCII 帧规则](https://www.modbus.org/file/secure/modbusoverserial.pdf)。采样位置按用户的 8950 LabVIEW 程序及实测返回确定，不自行替换为通用 Modbus TCP 寄存器模板。

### 8.2 设备 B 的实际返回

```text
ASCII：:010408506621B7FFFF002443\r\n
HEX：  3A 30 31 30 34 30 38 35 30 36 36 32 31 42 37 46 46 46 46 30 30 32 34 34 33 0D 0A
```

| 字段 | ASCII 内容 | 含义 |
| --- | --- | --- |
| 起始 | `:` | ASCII 帧起点 |
| 响应地址 | `01` | 设备 B 的实测地址字节 |
| 功能码 | `04` | 当前读取功能 |
| 数据长度 | `08` | 后续数据区的 8 字节 |
| 数据区 | `506621B7FFFF0024` | 按 LabVIEW 位置提取温湿度 |
| LRC | `43` | 校验字节 |
| 结束 | CRLF | `0D 0A` |

收到的网络帧是 ASCII 字符组成的 27 字节。偏移以冒号为 `0`，不是从 HEX 解码后的数据区起算。

### 8.3 温湿度换算

温度：取响应偏移 `11` 开始的 4 个字符 `21B7`，转为整数 `0x21B7`。正温算法：

```text
temperature = (word & 0x07FF) × 0.0625
            = 0x01B7 × 0.0625
            = 439 × 0.0625
            = 27.4375 ℃
```

GUI 保留两位小数，显示 `27.44℃`。上云驱动保留实际数值。

湿度：取偏移 `15` 开始的 4 个字符；正常值转为整数后除以 `10`。例如 `0237` 是十进制 `567`，得到 `56.7 %RH`。实测 `FFFF` 为 `65535`，不能显示成 `6553.5 %RH`。

设备 A 的实际示例是 `:1B040850662181FFFF00245F\r\n`，温度按同一算法为 `24.0625℃`，但地址字节是 `0x1B`。两台设备的地址配置不能直接互换。

GUI 自动显示本次响应地址；上云驱动则检查 `responseAddress`，不一致会拒绝本轮采样。两者都检查帧格式、功能码、长度与 LRC，并支持 TCP 分段接收。

### 8.4 校验、无效湿度与负温

LRC 校验针对 ASCII 十六进制解码后的字节：包含 LRC 的整段字节之和低 8 位须为 `0`。乱码、缺少 CRLF、数据长度错误、异常功能码或 LRC 错误均不作为有效采样。

命令行驱动只有配置列表明确包含 `65535` 才把 `FFFF` 当作已知无效湿度标记。其他超出 `0～100 %RH` 的湿度数据仍然报错。

原 LabVIEW 截图只提供正温分支。读到温度字的 `0x0800` 标记时，当前默认拒绝解析 / 上报。`signed12` 是命令行中仅供负温算法经确认后使用的选项；GUI 没有该切换，不能据此宣称已经支持负温。

## 9. 微信云开发接入

链路：`LH8950 → 采集电脑 TCP 驱动 → HTTPS deviceReport → 微信云数据库 → 手机小程序`。

手机读取云端数据，不直接连接局域网 XPort。电脑必须持续运行采集程序，并能访问互联网；手机不必与传感器处于同一个 Wi-Fi。

```text

```

### 9.1 云端需具备的条件

- `devices` 集合已有相应 `deviceId`，设备 `enabled` 未设为 `false`，密钥与采集配置一致。
- 已部署当前 `deviceReport`、`deviceList`、`deviceDetail`；新环境同时按小程序部署手册部署登录与告警相关函数。
- HTTP 网关 `/device-report` 路由关联 `deviceReport`，路由启用。具体控制台步骤见 [部署手册](../apps/wechat-miniprogram/部署手册.md)。

设备驱动使用 `HMAC-SHA256(secret, "deviceId:timestamp")` 十六进制签名，时间戳为毫秒。云端要求时间误差在 ±5 分钟内，当前设备上报节流间隔为 30 秒，故配置周期为 35 秒。

温度有效、湿度无效时，上报 `metrics: {temp: 实测温度}` 和 `metricQuality: {humidity: "invalid"}`。云函数替换最新指标和质量标记，避免显示过期湿度。湿度恢复有效时，后续上报会恢复数值显示。

### 9.2 手机查看

1. 在微信开发者工具生成预览二维码，由具有相应访问权限的微信扫码。
2. 手机上进入 **我的 → 数据连接 → 微信云开发 → 测试连接 → 保存连接**。
3. 回 **设备总览** 下拉刷新，搜索设备编号或「家庭温湿度」。

用户已在真实手机微信界面读到云端设备，设备 A 的真实温度与湿度无效已显示。预览版的访问 / 分享能力受微信平台限制，预览成功不等于已审核发布。

停止有效上报超过当前 90 秒阈值时，云端设备列表会显示离线。处理告警不会自动恢复传感器采集或修复探头。

### 9.3 后台采集与重启

本次设备 A 的后台进程信息位于小程序工程 `.local/lantronix/gateway-process.local.json`，记录进程编号、脚本、配置和输出 / 错误日志路径。进程编号会变化，不能照抄旧编号停止进程。

需要排查时读取状态文件，查看对应日志；停止前在任务管理器或 `Get-CimInstance Win32_Process` 中核对完整命令确实是目标脚本的 `--watch` 进程，再停止。

未配置开机自启。电脑重启后，需要重新运行 `python scripts/lhg8950_gateway.py --watch`。改动运行中配置文件后也要重启对应采集进程，因为参数在启动时读取。

## 10. 官方命令行查找与辅助诊断

在小程序工程目录执行：

```powershell
python scripts/find_xport.py --interface 192.168.31.122 --mac 00-20-4A-A6-FB-43
```

替换为当时电脑网卡 IP 和要找的设备 MAC。脚本从 Lantronix 官方下载 `dsearch.exe` 并检查预设 SHA256，结果与日志保存在 `.local/lantronix`。它只查找，不修改设备。

PowerShell 执行 npm 包装命令时用 `npm.cmd`，避免 `npm.ps1` 执行策略错误：

```powershell
npm.cmd run discover:xport -- --interface 192.168.31.122 --mac 00-20-4A-A6-FB-43
```

TCP 连通性检查：

```powershell
Test-NetConnection -ComputerName 192.168.31.201 -Port 10050
```

端口可连接只说明 TCP 服务开放，不能代替真实报文、LRC 与测量值验证。

## 11. 常见问题

| 现象 | 先检查 | 处理 |
| --- | --- | --- |
| 查不到 IP | 网口灯、所选网卡、模块标签 MAC | 有线直连后查找；有 Wireshark 时在查找期间重新上电观察 ARP |
| 提示不在同一网段 | 电脑地址 / 掩码与模块当前地址 | 选正确网卡，或按网段帮助配置电脑临时地址 |
| MAC 不匹配 | 输入标签、IP 是否属于另一台设备 | 停止修改，重新核对完整 MAC |
| 配置口无响应 | UDP 30718、网段、模块管理功能 | 核对配置口是否开启 / 只读；不要用 TCP 10050 代替 |
| 写入确认后仍连不上 | 新网段连接、电脑网卡、模块重启 | 切到新网段，再查 MAC / 读配置 / 读温度 |
| TCP 超时或拒绝连接 | 供电、IP、端口、是否被其他软件占用 | 关闭同模块其他读取程序，再进行只读测试 |
| 接收不足 27 字节 | HEX 的实际内容、等待时间、串口链路 | 保留原始 HEX，核对 LabVIEW 参数及设备串口；不猜改波特率 |
| 响应地址不一致 | 实际帧冒号后的两位 HEX | 配置正确 `responseAddress`；A 为 27，B 为 1 |
| 湿度无效 / FFFF | 探头连接及湿度通道 | 先检查探头，通讯正常不代表湿度通道正常 |
| LRC 失败 / 乱码 | 是否发真实字节、帧是否完整 | 发送原始查询帧，不发 HEX 文本、不附加 MBAP |
| 本地有温度、云端 404 | 云端是否注册对应 deviceId | 建立独立台账，避免与设备 A 共用编号 |
| 云端签名错误 | 配置与台账 secret 是否一致 | 对齐对应设备密钥，不使用测试设备密钥代替 |
| 云端时间戳超窗 | 电脑系统时间 | 校准系统时间后重试 |
| 云端节流跳过 | 是否有多个上报进程、是否小于 30 秒 | 保留一个进程，周期使用 35 秒 |
| 手机显示离线 | 采集进程、错误日志、lastReportTime | 恢复真实上报并刷新小程序 |
| EXE 停止后还有数字 | 状态是否标明已停止 | 数字是最后结果，需点开始才会刷新 |
